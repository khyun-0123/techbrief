## 1. 걸리는 시간 (11/27 실측)

앱 API를 **화면과 같은 순서**로 불러 쟀습니다. 사람이 읽고 고치는 시간은 뺐습니다.

| 무엇 | Vertex AI Gemma 4 26B (동시 16) |
| :-- | :-- |
| **키워드 → PPT, 처음 보는 키워드** (자료 최대 40건을 새로 요약) | **약 2분** (중앙 1분 42초, 48초~2분 7초, 키워드 4개) |
| **키워드 → PPT, 자료가 미리 요약된 키워드** | **약 1분** (중앙 48초, 40초~1분 36초) |
| 참고: OpenRouter Gemma 4 31B, 처음 보는 키워드 | 1분 53초 · 2분 29초 |
| 참고: 맥미니 gemma4:12b (한 번에 하나씩) | 자동 보고서 약 11분 |

* 예전(담당자 혼자) **4~5시간** → 도구 시간 **약 2분**. 발표의 「5분 안에 초안까지」는 이 실측의 가장 긴 경우도 넉넉히 들어가는 표현.

| 자료 종류 | Vertex 26B | OpenRouter 31B |
| :-- | --: | --: |
| 1차 · 기업 · 보도자료 | 7.6초 | 3.9초 |
| 1차 · 학회 | 7.6초 | 4.8초 |

### 요약된 자료 건수별 보고서 (Vertex)

| 보고서에 넣은 자료 | 5건 | 10건 | 20건 | 30건 | 10건 중 5건 새로 요약 | 10건 모두 새로 요약 |
| :-- | --: | --: | --: | --: | --: | --: |
| 걸린 시간 (중앙) | 26초 | 33초 | 62초 | 65초 | 약 43초 | 약 47초 |

* 10건이 넘으면 나눠 쓰고 합친다 (초안 50~60초). 단계: 초안 → AI 해설 보충 → 저장. PPT 내려받기 0.3초.

## 2. 왜 빨라졌나 — 동시 요청

* AI 연결마다 **「동시 요청 수」**를 둔다 (관리 페이지, 바로 적용). 맥미니는 모델 하나가 한 번에 하나씩 처리하므로 1, API는 여러 개.
* 요약 24건 기준 실측: 동시 1 = 194초 → 8 = 31초 → **16 = 23초** (Vertex, 실패 · 한도 초과 0).
* 사람이 누른 요청이 자동 작업보다 먼저 (AI 대기열 7단계 순서).

## 4. 측정 방법

* 측정용 서버(같은 코드 · 공용 DB · 자동 수집 끔)에서 스크립트로 `요약 API` → `보고서 작업 API`(1초마다 상태 확인) → `PPT 내려받기`를 화면과 같은 순서로 부름. 키워드 → PPT는 화면의 자동 선별(`src/autoPick.js`)을 그대로 씀.
* 조건마다 3~4회 중앙값. 측정 서버가 다시 켜진 시각과 겹친 회차는 뺌.
