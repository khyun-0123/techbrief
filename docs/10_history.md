# 10. 10주 과정 — 받은 피드백과 바꾼 것

> **이 문서로 알 수 있는 것**
> * 「기사 요약기」에서 「판정까지 하는 도구」가 되기까지
> * 피드백마다 무엇을 바꿨는지
> * 남은 한계와 다음 단계

## 1. 흐름

| 시기 | 한 일 |
| :-- | :-- |
| 10월 중순 | 고객사 인터뷰 — 문제 정의 (4~5시간 · 우리에게 주는 의미 · 일관된 보고서) ([01](01_requirements.md)) |
| 10월 말 | 중간발표 — **기사 요약기**: 모아서 요약하고 초안 쓰는 6단계. 그럴듯했지만 판단은 사람 몫 |
| 11월 초 | 1 · 2차 출처 연결, 중요도 재설계(새로움 30 · 보도량 10), AI 모델 13개 비교 → 교체 |
| 11월 중 | **특허 127만 건 축적 → 규칙 판정이 보고서 헤드라인으로**, 담당자 양식 PPT, 기술 시계열, 자동 보고서 |
| 11월 말 | 데모 발표 → 운영 서버 이전, 관리 페이지(AI 연결 · 수집 출처 · 판정 기준), AI 동시 처리, 모델 평가 · 시간 실측 |

## 2. 받은 말 → 바꾼 것

| 들은 말 | 바꾼 것 |
| :-- | :-- |
| 「기존 AI와 차별점이 없어 보인다」 (11월 중 자문) | 그날 특허를 쌓기 시작 → **127만 건**, 규칙 판정 · 같은 키워드면 같은 결과 ([03](03_judgment.md)) |
| 「기사가 많다고 중요한 것은 아니다」 (고객사) | 새로움 중심 100점, 보도량은 10점만 → **「중요」 62개** ([04](04_collection_importance.md)) |
| 「너무 느리다」 (멘토링) | 모델 비교 뒤 교체 · 미리 요약 · 동시 처리 → **키워드부터 PPT까지 약 2분** ([06](06_model_evaluation.md) · [07](07_performance_ops.md)) |
| 「GPT에 프롬프트를 잘 쓰면 되지 않나」 (IR 리허설) | GPT 보고서와 나란히 비교 — 판정 · 특허 · 원문 대조가 다름 ([05](05_ai_and_evidence.md)) |
| 「환각은 어떻게 막나」 (IR 리허설) | 근거 대조 네 겹 · 「확인할 점」을 맨 위에 ([05](05_ai_and_evidence.md)) |
| 「출처 범위 · 놓치는 것은?」 (IR 리허설) | 62개는 순서일 뿐 · 「자주 찾은 새 키워드」 · 출처마다 저장 0건 경고 ([04](04_collection_importance.md)) |
| 「보고서 양식은 4:3 · 1페이지 + 유첨」 (고객사 회신) | 담당자 양식 PPT, 미리보기 · PDF도 같은 쪽 |

## 3. 틀렸던 것도 기록했다

| 그때 | 지금 |
| :-- | :-- |
| OLED · LCD 같은 성숙 기술을 「연구 중」으로 판정 | 특허로 기술 단계 판정 → 12개 중 7 → **10개** 맞힘 |
| AI가 「자사 2배 증가」를 「경쟁사 대비 2배」로 바꿔 씀 | 근거와 숫자를 대조해 다르면 「확인할 점」으로 알림 |

## 4. 남은 것 · 다음 단계

* **사람이 확인 · 수정하는 시간은 아직 재지 않았다** → 앱이 「보고서 완성 → 내려받기」를 기록하도록 해 두었고, 기능 확정 뒤 시범 사용에서 잰다.
* 판정 기준값은 기준을 맞춘 12개로 시험 → 담당자 검수 · 새 기술로 다시 확인.
* 모든 AI 모델의 「실무」 점수가 낮다 → 요약 양식(기사에 없는 칸까지 채우게 한 것)부터 고친다.
* 특허는 제목 · 분류로 셈 → 초록 · 인용으로 넓히기.
