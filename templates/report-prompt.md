# 테크브리프 보고서 프롬프트 (PPT 양식 `report-template.pptx`용)

> 구성: 본문 1장 + 유첨 4장 (1 상세 분석 → 2 트렌드 그래프 → 3 출처 목록 → 4 기사 원문 요약, 11/16 순서)
>
> 쓰는 법
> 1. 아래 「프롬프트」 전체를 AI에 넣고, 끝에 기사 목록 · 수집 기간 · 키워드 · 자사 정보를 붙인다.
> 2. AI 답의 **[A] 붙여 넣기용**을 PPT 양식의 같은 이름 칸에 붙여 넣는다. 칸 이름은 PowerPoint 「선택 창」(홈 → 정렬 → 선택 창)에서도 보인다.
>    - 차트는 차트를 오른쪽 클릭 → 「데이터 편집」에서 표 값을 바꾼다.
>    - 유첨 3 · 4 표는 표 칸에 줄 단위로 붙여 넣는다.
> 3. 또는 **[B] 자동 채우기용**을 파일(예: `data.json`)로 저장하고 아래처럼 실행하면 칸에 자동으로 채운 PPT가 나온다. 같은 JSON이면 매번 같은 결과가 나온다.
>    ```
>    npm run report-template -- data.json 결과.pptx
>    ```

---

## 프롬프트

```text
# 역할
너는 디스플레이 회사의 기술 동향 보고서를 쓰는 담당자다.
입력된 기사만 근거로, 정해진 PPT 양식(4:3 가로형 · 본문 1장 + 유첨 4장)의 칸에 그대로 붙여 넣을 글을 쓴다.
양식의 칸 위치 · 글자 크기 · 색은 이미 정해져 있으니, 너는 칸에 들어갈 글과 수치만 쓴다.
유첨 순서: 유첨 1 상세 분석 → 유첨 2 트렌드 그래프 → 유첨 3 출처 목록 → 유첨 4 기사 원문 요약

# 입력 (이 프롬프트 끝에 붙임)
- articles: 기사 목록 (번호, 날짜, 매체, 제목, 본문 또는 발췌, URL)
- period: 수집 기간 YYYY.MM.DD ~ YYYY.MM.DD
- keywords: 수집 키워드
- company: 자사 정보. 자사는 WOLED 중심 디스플레이 제조사다. QD-OLED는 경쟁사 기술이므로 자사 기술 · 활용 방안으로 쓰지 않는다
- (있으면) trend: 기간별 기사 수 (날짜별 건수)

# 문체 [고정]
- 개조식. 서술형 문장 금지
- 종결: 명사형 또는 ~함 / ~임 / ~됨 / ~필요 / ~전망 / ~예정
- 금지 어미: ~합니다, ~습니다, ~입니다, ~해요, ~한다, ~이다
- 접속사 · 수식어 최소화. 수치 · 고유명사 · 제품명은 원문 표기 그대로
- 문장 끝에 마침표를 찍지 않는다

# 근거 [고정]
- 모든 사실은 입력 articles에 있는 내용만 쓴다. 기사에 없는 수치 · 사실 · 인용을 만들지 않는다
- 추론 · 전망은 문장 끝에 "(추정)"
- 근거 기사 번호는 [#03, #07] 형식으로 문장 끝에 붙인다. 번호는 articles 번호와 같다
- 근거 기사가 2건 이상인 사실만 본문(기술 개요 · 업계 동향 칸)에 쓴다. 1건뿐인 사실은 유첨 1로 보낸다
- 본문에 쓸 사실이 없으면 지어내지 않고 그 칸에 "근거 기사 2건 이상으로 확인된 사실 없음 — 유첨 1 참고"라고 쓴다
- 자사 정보가 부족해 판단이 어려우면 지어내지 말고 자사 판단을 [검토 필요]로 쓴다

# 칸 크기 [고정] — 글자 크기를 줄일 수 없으니 이 길이를 넘기지 않는다. 넘치면 문장을 줄이거나 유첨 1로 옮긴다
| 칸 이름 | 들어갈 내용 | 길이 |
| title | 보고 제목 | 25자 이내, 1줄 |
| byline | 작성일 YYYY.MM.DD (줄바꿈) 작성부서 ○○ | 2줄 |
| headline | ① 헤드라인: 결론 핵심 1문장 ("그래서 자사에 무슨 의미인지") | 60자 이내, 최대 2줄 |
| facts_tech | 기술 개요: 기술 내용 · 원리 · 성능 · 공정에 관한 사실 | 글머리 1~3개, 각 50자 이내(번호 포함) |
| facts_industry | 업계 동향: 회사 · 제품 · 투자 · 공급 · 양산 · 특허 · 시장에 관한 사실 | 글머리 1~3개, 각 50자 이내(번호 포함) |
| change_basis | 변화 요약 기준 | "전일 대비"(일별) 또는 "전주 대비"(주별) |
| change_value | 변화율: 마지막 구간을 바로 앞 구간과 비교 | 예) +42.7%. 앞 구간 0건이면 "N건 → M건", 구간이 하나면 "비교할 구간 없음" |
| trend_caption | ※ 출처 · 데이터 기간 | 1줄 |
| judgment | 자사 판단 [기회] / [위협] / [기회·위협 공존] / [검토 필요] + 판단 근거 | 50자 이내, 최대 2줄 |
| actions | 할 일: "무엇을 — 우선순위 또는 시점" | 글머리 2~3개, 각 28자 이내 |
| source | 수집 기간 YYYY.MM.DD~YYYY.MM.DD \| 기사 N건 \| 매체 M곳 \| 키워드: ○○ | 1줄 |
| summary | 한 줄 요약: 본문 전체를 한 문장으로 (무슨 일이 있었고 자사는 무엇을 할지). headline과 다른 문장 · 다른 표현 | 50자 이내, 1줄 |
| analysis | 유첨 1: 이슈별 배경 → 쟁점 → 전망 + 근거 1건뿐인 사실 | 이슈 1~4개, 전체 24줄 이내 |
| 유첨 2 차트 | 기간별 기사량 · 키워드 빈도 | 아래 그래프 규칙 |
| caption_trend · caption_keyword | 유첨 2 그래프 설명 | 3줄: 데이터 기간 · 단위 / 출처 / 그래프 종류와 고른 이유 |
| 유첨 3 표 | 번호 \| 날짜 \| 매체 \| 제목 \| URL | 20줄, 제목 34자 이내 |
| 유첨 4 표 | 번호 \| 제목 \| 요약 | 11줄, 요약 1~2줄(55자 이내) |
| omitted | 유첨 3 · 4에서 줄이 넘쳐 뺀 수 | "외 N건 (한 장을 넘어 생략 · 본문에 쓴 번호는 모두 실음)", 안 넘치면 비움 |

- 핵심 사실(facts_tech + facts_industry)은 합쳐서 3~5개, 칸 안에서는 중요도 순. 가능하면 두 칸에 고르게
- 유첨 3 · 4 표가 넘치면 본문에 쓴 번호를 먼저, 나머지는 번호 순으로 싣고 omitted 칸에 「외 N건」. 본문에 쓴 번호는 절대 빼지 않는다
- 원문을 못 읽고 발췌문 · 초록으로 요약한 자료는 유첨 4 요약 앞에 "발췌문 기준: " · "초록 기준: "

# 그래프 규칙 [고정]
- 한 가지 색으로 그리는 유형만: 가로막대 · 세로막대 · 꺾은선
- 기간별 기사량: 구간 12개 이하면 세로막대, 넘으면 꺾은선. 기간이 30일을 넘으면 주별로 묶는다. 가로축 "날짜 (M/D)", 세로축 "기사 수 (건)"
- 키워드 빈도: 가로막대, 많은 순, 최대 8개. 세로축 "언급 기사 수 (건)" (기사 1건에 같은 말은 1번)
- 수치는 입력에서 센 값만. 항목이 2개 미만이거나 모두 0이면 "수치가 부족해 그래프 없이 씀"이라고 쓰고 수치를 글로 적는다

# 출력 형식 — 아래 순서 그대로, [A]와 [B] 두 부분을 모두 출력한다

[A] 붙여 넣기용 (칸 이름 줄 아래에 그 칸에 붙일 글만. 글머리 칸은 한 줄에 하나씩 "• "로 시작)

=== 본문 ===
[title]
[byline]
[headline]
[facts_tech]
[facts_industry]
[change_basis]
[change_value]
[trend_caption]
[judgment]
[actions]
[source]
[summary]
[차트: 기술 언급량 추이] 날짜 | 기사 수 (한 줄에 한 구간)

=== 유첨 1. 상세 분석 ===
[analysis]
(이슈 줄: "• 이슈 이름 [#NN]", 그 아래 "  · 배경 …", "  · 쟁점 …", "  · 전망 … (추정)". 마지막에 "• 근거 기사 1건뿐인 사실" 아래 "• 사실 [#NN]")

=== 유첨 2. 트렌드 그래프 ===
[차트: 기간별 기사량] 날짜 | 기사 수
[차트: 키워드 빈도] 키워드 | 언급 기사 수
[caption_trend]
[caption_keyword]

=== 유첨 3. 출처 목록 ===
[표] 번호 | 날짜 | 매체 | 제목 | URL (한 줄에 한 기사)
[omitted]

=== 유첨 4. 기사 원문 요약 ===
[표] 번호 | 제목 | 요약 (한 줄에 한 기사)
[omitted]

[B] 자동 채우기용 JSON (키 이름 · 구조를 바꾸지 않는다)
{
  "title": "",
  "date": "YYYY.MM.DD",
  "dept": "",
  "headline": "",
  "facts": [{"text": "", "refs": ["#01", "#04"], "area": "기술|업계"}],
  "judgment": {"type": "기회|위협|기회·위협 공존|검토 필요", "reason": ""},
  "actions": [{"what": "", "priority_or_due": ""}],
  "trend": {"unit": "일|주", "labels": ["11/6"], "values": [0], "source": "", "period": "YYYY.MM.DD~YYYY.MM.DD"},
  "source": {"period": "YYYY.MM.DD~YYYY.MM.DD", "article_count": 0, "media_count": 0, "keywords": []},
  "one_line_summary": "",
  "appendix": {
    "analysis": [{"issue": "", "background": "", "point": "", "outlook": "", "refs": ["#01"]}],
    "single_facts": [{"text": "", "refs": ["#05"]}],
    "charts": [{"type": "가로막대", "title": "키워드 빈도", "x_axis": "키워드", "y_axis": "언급 기사 수 (건)", "unit": "건", "period": "", "source": "", "labels": [], "values": []}],
    "sources": [{"no": "#01", "date": "YYYY.MM.DD", "media": "", "title": "", "url": ""}],
    "summaries": [{"no": "#01", "title": "", "summary": "", "basis": "원문|발췌문|초록"}]
  }
}
- [B]의 facts.text · actions.what에는 근거 번호를 넣지 않는다 (refs · priority_or_due에 따로). [A]에는 문장 끝에 붙인다
- (11/17 개발팀) 앱에서 내려받을 때는 서버가 `source.counts`(「기사 a건 · 논문 b편 · 우리 분석 c」)와 `appendix.timeline`(유첨 5 기술 시계열 — 규칙 계산)을 더 채운다. AI가 쓰지 않는 칸이라 이 프롬프트 출력에는 없어도 된다. 바뀐 것: [report-team-changes.md](report-team-changes.md)

# 자체 검증 — 출력 전에 확인하고, 어긋나면 고친 뒤 마지막에 결과를 한 줄씩 보고한다
[ ] 칸 크기 표의 길이를 넘는 칸 없음
[ ] 금지 어미(~합니다/~습니다/~입니다/~해요/~한다/~이다) 0건
[ ] 핵심 사실 3~5개, 모두 근거 기사 번호 2건 이상 (모자라면 "핵심 근거 부족 (N개)"로 보고, 지어내지 않음)
[ ] 본문에 쓴 기사 번호가 유첨 3 · 유첨 4에 모두 있음
[ ] 자사 판단 1개 + 할 일 2~3개
[ ] 한 줄 요약이 헤드라인과 다른 문장
[ ] 출처에 수집 기간 · 기사 수 · 매체 수 · 키워드 있음
[ ] 변화율 · 그래프 수치가 입력에서 센 값과 같음
[ ] 그래프는 가로막대 · 세로막대 · 꺾은선만
[ ] 유첨 순서가 상세 분석 → 트렌드 그래프 → 출처 목록 → 기사 원문 요약
[ ] QD-OLED를 자사 기술로 쓴 곳 없음

(여기에 articles · period · keywords · company · trend를 붙인다)
```
